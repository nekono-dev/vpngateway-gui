# パスワードマネージャ対応フォーム（Proton Pass実機検証の知見）

WebアプリのフォームでProton Pass等のパスワードマネージャが自動入力・新パスワード生成を行えるようにする／直すための手順。Proton Passの実機で検証した知見で、他のパスワードマネージャでは未検証。**原因は推測では当たらない**（実機で何度も外れた）。下の「疑うポイント」で静的に当たりを付け、外れたら「切り分け手順」で1要因ずつ実機検証する。

## 最初にやること

1. 静的監査を実行する（Node.jsのみで動き、依存パッケージなし。JSX/TSX（`*.tsx`、テストを除く）を走査し、既知の落とし穴を指摘する）。パスは、このskillの置き場所に読み替える。

   ```bash
   node <skillのパス>/scripts/audit-forms.mjs <ソースのディレクトリまたはファイル...>   # 省略時はsrc
   ```

   `ERROR`は既知の原因そのもの、`WARN`は目視確認が要るもの。終了コードは`ERROR`があれば1。
2. 新しくフォームを作るときは、`templates/`の雛形をコピーして使う（下の「雛形」）。
3. 監査が通っても直らない場合だけ、実機の切り分けに進む。**手順を利用者に頼むときは、主語（どのブラウザ・どのページで何をするか）と、貼ってほしい出力を明記する**（「貼り付けて」だけでは何を貼るのか伝わらない）。

## 疑うポイント（実機で確定した事実。可能性の高い順ではなく、確認の漏れを防ぐ順）

| # | 症状 | 原因 | 対処 |
|---|---|---|---|
| 1 | フォームが出ない | `autocomplete="off"`（またはautocomplete無指定） | ユーザー名`username`・現在のパスワード`current-password`・新パスワード`new-password` |
| 2 | 出るが候補が見えない／押せない | モーダル`<dialog>`（`showModal()`）はトップレイヤーに描画され、拡張機能の候補表示が隠れる | パスワード欄を持つダイアログは非モーダル（`dialog.show()`。`non-modal-dialog.css`で中央に固定し、背面は`box-shadow`で暗くする） |
| 3 | ダイアログを開いても反応しない | 閉じた`<dialog>`内のフォームは0×0で、開いても再検出されない | `{open ? <Form /> : null}`で、開いたときにだけDOMへ追加する |
| 4 | 新パスワードの生成が現在のパスワード欄に入る | 変更フォームにユーザー名欄が無い、または「新しいユーザー名」の別text欄がある（位置・autocompleteによらず分類が崩れる） | 欄順は「ユーザー名(`username`)・現在のパスワード・新パスワード」の3欄。ユーザー名の変更は`username`欄の書き換えで行う（現在値で初期化し、書き換えた場合だけ送る） |
| 5 | 出るが入力されない（パスワード再入力のダイアログ等） | ユーザー名欄が無い／非表示（opacity 0・1px・`readOnly`・`aria-hidden`）の欄は検出されない | 可視の`username`欄を置く（パスワード再入力だけを求めるダイアログも、ログイン中のユーザー名を`defaultValue`で表示する） |
| 6 | 確認欄と誤判定される | ラベルに「確認」「再入力」を含む | 「ログインパスワード」のように避ける |
| 7 | **ユーザー名だけ入り、パスワードが入らない／フォームが消える** | **同じ`<form>`にパスワード欄と2段階認証欄（OTP）がある**（`autocomplete`の値によらず）。2段階認証欄と送信ボタンを`<form>`の外に出して`form`属性で関連づける案は、静的ページでは通るがアプリ内では通らない（`<main>`全体がフォーム扱いされた） | `<form>`にはユーザー名・パスワード・送信ボタンだけを置く。2段階認証欄は、ボタンを押したときに追加する（追加後はPassのフォームが出ないので、先に自動入力させる） |

**原因ではなかったこと**（疑わなくてよい）: React制御の入力欄／送信ボタンの`disabled`／`placeholder`・`inputMode`／アプリのCSS／URL・`<head>`・manifest／アプリのスクリプトの有無／祖先要素。読み込み時点にフォームが無いこと（動的追加）も問題ない。

## 切り分け手順（監査で当たらなかった場合）

実機でしか分からないので、1回に1要因だけを変えて、利用者に試してもらう。

1. **属性の実測**: フォームを開いた状態（入力欄は未クリック）で、利用者のブラウザのコンソールに`scripts/dom-probe.js`の「1. 入力欄の一覧」「2. 祖先とPassの印」を貼ってもらい、出力を貼り返してもらう。`autocomplete`・可視サイズ・`data-protonpass-form`が付いた祖先を見る。
2. **イベント記録**: 同ファイルの「3. 自動入力の記録」を貼ってから候補を選んでもらう。パスワード欄にイベントが1つも来ない＝Passがパスワードを入力しようとしていない（フォーム分類の問題）。イベントが来て値が消える＝Reactの再描画の問題。
3. **構成違いの並置テスト**: `node <skillのパス>/scripts/make-bisect-page.mjs <出力先>`で`pw-test.html`を生成し、静的に配信される場所（例: Viteなら`public/`）へ置いて検証環境へ反映する。利用者に各ブロックの「ユーザー名」欄で候補を選んでもらい、**ブロックごとに「両方入った／ユーザー名だけ／どちらも入らない」を報告**してもらう。ブロックの構成は`scripts/make-bisect-page.mjs`の`VARIANTS`を編集して増やす（1回に1要因だけ変える）。
4. 静的ページで通りアプリで通らないときは、**アプリの実DOMを写して比較**する（`dom-probe.js`の「4. フォームを写す」）。実DOMの祖先・兄弟要素・`form`属性の使い方まで、テストページと突き合わせる。複製をアプリ上に置いて試す場合、Passが付けた`protonpass-*`要素・属性が複製に混ざり、結果が汚染される点に注意する（毎回新しく読み込む）。
5. 切り分けが終わったら**テストページを必ず削除**する（`pw-test*.html`。コミットしない。検証環境からも消す）。

## 検証の注意

- 実ブラウザ（利用者のProton Pass）でしか確認できない。jsdomなどの単体テストでは拡張機能の挙動は見えない。
- 試すたびにページは**強制再読み込み（Ctrl+Shift+R）**してもらう。
- 保存の通知（「ログインを保存しますか？」）が出るかも別に確認する。「自動入力は使うが保存はさせない」要件がある場合は、保存の通知が出ないこと（出た場合は「保存しない」を選べて次回出ないこと）まで見る。
- jsdomは`<dialog>`の`show()`/`showModal()`を実装していない。単体テストでは`open`属性を切り替えるポリフィルが要る。
- 判明した事実と検証結果は、プロジェクトの設計書・作業記録へ残す。

## 雛形（`templates/`）

| ファイル | 用途 |
|---|---|
| `LoginForm.template.tsx` | ユーザー名＋パスワード（＋任意の2段階認証をボタンで追加）。ログインフォームの原型 |
| `ChangePasswordForm.template.tsx` | ユーザー名・現在のパスワード・新パスワードの3欄。資格情報の変更フォームの原型 |
| `NonModalPasswordDialog.template.tsx` | パスワード欄を持つ非モーダルのダイアログ（開いたときだけフォームを描画、Escで閉じる。パスワード再入力の確認ダイアログの原型） |
| `non-modal-dialog.css` | `dialog.non-modal`のスタイル |

雛形はReact（TypeScript）の単体ファイルで、プロジェクト固有の部品に依存しない。コピー後、`TODO`の箇所（API呼び出し、文言、現在のユーザー名の取得）を埋める。
