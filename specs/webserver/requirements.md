# 責務の範囲

Webサーバは以下のみを責務とし、業務ロジック（VPN接続状態の判定、コマンド解決、権限チェック等）を一切持たない。

- GUIの表示
- APIサーバへのリクエスト送信（kick）
- 実行結果・状態のユーザ表示
- ブラウザから見て同一オリジンとなるよう `/api/*` をAPIサーバへリバースプロキシすること

# 画面構成

| 画面 | 内容 |
|---|---|
| 接続状態ダッシュボード | 現在のVPN接続状態（接続中/切断/エラー）、接続中のベンダー・国、透過ゲートウェイ／明示的プロキシそれぞれの稼働状況を表示する（設定値ではなく実際の適用状態。`GET /v1/connection/gateway`。Phase 5時点で明示的プロキシは未実装のため「未対応」と表示し、Phase 4で実状態表示に置き換える）。設定ダイアログを開くための設定ボタンを配置する。VPNベンダーへのログイン代行を開始するボタンを配置する（`POST /v1/session`、Phase 2で前倒し実装。`wbs/phase2.md`参照） |
| 接続操作 | 接続先リスト（後述「接続先リスト」。ベンダーCLIが返す接続可能な接続先のみをping値の小さい順に提示し、自由入力は行わない）、接続/切断ボタン、接続中に現在と異なる接続先を選択した場合の「接続先を変更」ボタン（Phase 8）。ベンダー選択は行わない |
| 設定ダイアログ | ダッシュボードの設定ボタンからモーダルダイアログとして開き、APIサーバが保持するユーザ向け設定（`GET`/`PUT` `/v1/settings`）をトグル・テキストボックスで編集する。ページ遷移は行わず、保存はダイアログ内の保存ボタン押下時に一括で `PUT` する |
| 接続ログ | 過去の接続・切断・エラーの履歴表示（APIサーバの監査ログを参照） |

## 設定ダイアログの入力項目

ユーザ向け設定の各項目を、以下のUI部品で編集可能にする。

| 設定項目 | UI部品 | 備考 |
|---|---|---|
| `killSwitch` | トグルスイッチ | ONでVPN切断検知時にLAN側通信を遮断する |
| `excludedDomains` | テキストボックスのリスト編集（追加・削除可能な複数行入力） | split-tunnelで除外する宛先ドメイン。1行1ドメインとして入力し、保存時に配列へ変換する |
| `transparentGatewayEnabled` | トグルスイッチ | 透過ゲートウェイモードの有効/無効 |
| `explicitProxyEnabled` | トグルスイッチ | 明示的SOCKS5/HTTPプロキシモードの有効/無効 |
| `explicitProxyAllowedCidrs` | テキストボックスのリスト編集（追加・削除可能な複数行入力） | 明示的プロキシモードで接続を許可するLAN側CIDR。1行1CIDRとして入力し、保存時に配列へ変換する |

`explicitProxyEnabled` がOFFの間は `explicitProxyAllowedCidrs` の入力欄を無効化（disabled）し、設定自体は保持したまま編集不可であることを視覚的に示す。

`defaultCountry`（デフォルト接続国）は廃止した（Phase 8）。接続処理に一度も使われていなかったうえ、「最後に接続した接続先」をシステムが記憶して既定選択とする方が利用者の意図に沿うため（下記「接続先リスト」参照）。

## 接続先リスト（Phase 8）

接続操作カードの接続先選択は、ドロップダウンに代えて、ping値に基づくグラフィカルなリストとする。

- **提示内容**: VPNベンダーCLIが返す接続先（国・都市）の一覧。1行が1接続先（都市単位。同一国に複数都市がある場合は別行）。各行に国コード、国名、都市名、ping値（ミリ秒）を表示する。ping値が取得できない接続先は「-」と表示し末尾に置く。
- **並び順**: ping値の小さい（速い）順。全タブ共通。
- **タブ**: 「すべて」（全接続先）と「お気に入り」（利用者がお気に入り登録した接続先のみ）を切り替えて表示できる。どちらのタブもping値の小さい順とし、「すべて」タブではお気に入りの接続先に★マークを表示する。
- **お気に入り**: 各行の★ボタンで登録・解除する。登録内容はAPIサーバに永続化し、再読み込み・別端末・別ブラウザでも共通とする（認証がなくLAN限定の運用のため、利用者全員で共有される）。お気に入りが0件のときは、その旨と登録方法を案内する。
- **絞り込み**: 国名・都市名・国コードのテキスト入力で、表示中のタブのリストを絞り込める（大文字小文字は区別しない）。並び順は変えない。
- **選択と既定選択**: 行をクリックして接続先を選択する（1つのみ）。未選択の間は、接続中なら現在の接続先、切断中なら最後に接続した接続先を選択済みとして扱い、リスト上で識別できるようにする。現在の接続先には「接続中」、最後に接続した接続先には「前回」のバッジを付ける。
- **接続ボタン**: 切断中に、選択済みの接続先（未選択なら最後に接続した接続先）へ接続する。選択済みの接続先が無い場合は操作不能とする。
- **「接続先を変更」ボタン**: 接続中に、現在の接続先と異なる接続先が選択されている間だけ、切断ボタンとは別に表示する。押下すると選択した接続先へ切り替える（切断ボタンは常に残す）。確認ダイアログは設けない。
- **再計測**: 「再計測」ボタンでリストを再取得し、ping値を更新する（ping値は取得時点の推定値であり、自動更新はしない。リスト表示中に並び順が勝手に変わるのを避けるため）。取得中はローディングを表示し、二重取得できないようにする。
- **取得失敗**: リストの取得に失敗した場合（未ログイン・プロキシ未応答等）は、リスト領域にエラー要約と「再取得」ボタンを表示し、接続操作は行えない（切断は可能）。
- **設定ダイアログとの関係**: 接続先の選択は設定ダイアログではなくこのリストに一本化する。

## 未実装機能の暫定表示（Phase 5〜Phase 6。明示的プロキシ分はPhase 4で除去済み）

`excludedDomains`（Phase 6）はWeb UIから設定値の編集・保存ができるが、対応するproxy側処理が実装されるまで実際には反映されない。利用者が「保存できた＝効いている」と誤解しないよう、該当する設定項目に「未対応（反映されません）」の旨を表示すること。対応フェーズ完了時に除去する。明示的プロキシはPhase 4で実装済みのため暫定表示の対象外とし、稼働状況欄に実際の稼働状況（稼働中・停止・未構成・起動失敗の繰り返し等）を表示する。

# Web⇄API通信の要件

ブラウザは常にWebサーバの単一オリジンにのみアクセスし、Webサーバが `/api/*` パス配下のリクエストをAPIサーバへリバースプロキシする必要がある。これによりブラウザ視点でのCORS設定が不要になる。また、APIコンテナはホストポートを公開せず内部ネットワークのみに存在させることができ、LAN上の攻撃対象をWebサーバの1ポートに絞れる。

現時点で認証機構はないが、将来Cookieベースのセッション認証を追加する場合も、この同一オリジン構成であればドメイン分離に起因する問題（Cookie共有不可等）が生じないことが求められる。

# 状態管理の要件

- VPN接続状態、Kill Switch状態等を、画面表示中はAPIサーバから定期的に取得できること。接続先リスト（ping値を含む）は定期取得の対象とせず、画面表示時と利用者の再計測操作時にのみ取得する。
- 接続/切断等の操作リクエスト送信中はUI上で操作を二重送信不可にし、完了までローディング状態を表示すること。
- APIサーバからのエラーレスポンスは、ユーザに分かる形でトースト表示等に変換すること。生のエラーメッセージ（コマンドのstderr等）は詳細表示（折りたたみ）に留め、通常表示では要約のみとする。
