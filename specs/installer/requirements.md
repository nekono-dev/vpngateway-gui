# インストーラ 要件定義書

## 1. 目的

クリーンなDebian系サーバへ、VPNゲートウェイの全サービスを1コマンドで導入し、運用者がDockerや設定ファイルを事前に用意せずに使い始められるようにする。サービスを構成する3つの実行単位を別々のホストへ分離配置でき、実行単位間の通信を保護する証明書も導入時に自動で配布する。

## 2. スコープ

### 2.1 対象

- Debian・Raspberry Pi OS・Ubuntu への導入、更新、修復、アンインストール。
- ロールごとの配置先ホストの指定と、リモートホストへの配布。
- 通信路の保護に用いる自己署名証明書の生成と配布。
- 導入用スクリプトの頒布。

### 2.2 対象外

- Docker本体と依存パッケージの削除。
- 外部認証局との連携と、証明書の失効・自動更新。
- 踏み台や多段のSSH経由での配置。

## 3. 前提

- なし

## 4. 機能要件

- FR-1: インストーラは、事前検査・依存導入・環境設定・起動までを、1回の呼び出しで完了する。
- FR-2: インストーラは、有効にするベンダーを引数で指定でき、省略時はバンドルのある全ベンダーを有効にする。
- FR-3: インストーラは、Web UIの公開ポートを引数で指定でき、省略時は既存の設定値を使い、設定が無ければ443にする。
- FR-4: インストーラは、再実行で更新・ベンダーの変更・修復を行い、既存の設定とログイン情報を保持する。
- FR-5: インストーラは、ロールごとの配置先ホストを引数で指定でき、指定しないロールは実行したホストへ配置する。
- FR-6: インストーラは、全リモートホストへの到達性を変更の前に検査し、1台でも到達できなければ何も変更せず停止する。
- FR-7: インストーラは、記録済みの配置先と異なる指定での再実行を、何も変更せずに拒否する。
- FR-8: インストーラは、実行単位間の通信用の自己署名証明書を生成して配布し、認証局の秘密鍵を配布しない。
- FR-9: インストーラは、ホストへの永続的な変更を、IPフォワーディングの設定・起動時の遮断ガード・再起動の依頼受付に限定する。
- FR-10: インストーラは、導入したものを後始末するアンインストールを提供し、設定とログイン情報は既定で残す。
- FR-11: 頒布は、取得するソースのコミットを固定したスクリプトをCIで生成し、利用者へ1つのURLで提供する。
- FR-12: ベンダー固有のホスト側の手順は、ベンダーバンドル内に分離し、共通のインストーラはその内容を知らない。

## 5. 非機能要件

- NFR-1: 同じ引数での再実行で、内容が変わる設定ファイルは0件とする。
- NFR-2: 証明書と秘密鍵の置き場の権限は所有者のみとし、配布物に含まれる認証局の秘密鍵は0件とする。
- NFR-3: Web UIの起動確認は、最大180秒で打ち切って失敗とする。
- NFR-4: ポート番号は1から65535、ベンダーIDは英小文字で始まる32文字以内に限り、違反は何も変更せずに拒否する。
- NFR-5: インストーラの自動検査は、root権限とネットワークなしで実行でき、失敗が0件である。

## 6. 受け入れ条件

- AC-1 (FR-1): 本体インストーラの起点が、事前検査・依存導入・設定・起動の各工程をこの順に呼び、構文が正しい。`tests/installer/setup.test.ts`
- AC-2 (FR-2): ベンダーを指定しないと全バンドルが有効になり、指定すると指定した集合だけが有効になる。`tests/installer/setup.test.ts`
- AC-3 (FR-3): ポートを省略すると既存の設定値、設定が無ければ443になり、範囲外の値は拒否される。`tests/installer/setup.test.ts`
- AC-4 (FR-4): 設定の更新は他の行を保持し、同じ値での更新を繰り返しても内容が変わらない。`tests/installer/setup.test.ts`
- AC-5 (FR-5): 配置先を指定しないロールはローカルに、指定したロールはそのホストに決まる。`tests/installer/topology.test.ts`
- AC-6 (FR-6): 到達できないホストを指定すると、設定ファイルを書く前に停止する。`tests/installer/topology.test.ts`
- AC-7 (FR-7): 記録済みと異なる配置先の指定は、停止して理由を示す。`tests/installer/topology.test.ts`
- AC-8 (FR-8): 生成された各サーバ証明書は対応する認証局で検証でき、生成物に認証局の秘密鍵が含まれない。`tests/installer/pki.test.ts`
- AC-9 (FR-9): インストーラが書き込むホスト上のパスは、定義された設定ファイル・ユニット・ディレクトリに限られ、アンインストールが全てを撤去する。`tests/installer/setup.test.ts`
- AC-10 (FR-10): アンインストールは、配置先の指定と併用できず、データ保持の指定はアンインストール以外では拒否される。`tests/installer/setup.test.ts`
- AC-11 (FR-11): 頒布用スクリプトの生成は、指定したコミットを埋め込み、不正な指定を拒否する。`tests/installer/distribution.test.ts`
- AC-12 (FR-12): ベンダーのホスト側の手順は、存在するバンドルについてだけ、そのバンドルの場所で実行される。`tests/installer/setup.test.ts`
- AC-13 (NFR-1): 同じ引数でポートとベンダーを決定して設定を2回書いても、設定ファイルの内容が変わらない。`tests/installer/setup.test.ts`
- AC-14 (NFR-2): 配置後の証明書の置き場の権限は700、秘密鍵の権限は600であり、認証局の秘密鍵が存在しない。`tests/installer/pki.test.ts`
- AC-15 (NFR-3): Web UIの起動確認の待機は、180秒を上限とする。`tests/installer/setup.test.ts`
- AC-16 (NFR-4): 範囲外のポートと不正なベンダーIDを含む設定は、検査で拒否される。`tests/installer/setup.test.ts`
- AC-17 (NFR-5): 同梱の自動検査を、一般ユーザーで実行すると、失敗が0件で終了する。`tests/installer/setup.test.ts`
