# APIサーバ 要件定義書

## 1. 目的

Web UIからの命令を受け、管理者が用意したプロファイルに従って検証し、VPNベンダーCLIのコマンドへ解決してゲートウェイへ送る。ベンダーごとの機能差とプラン制限を、コードの分岐ではなくプロファイルの宣言で扱い、利用者の操作可否と状態をWeb UIへ一貫して返す。

## 2. スコープ

### 2.1 対象

- プロファイルの検証と、コマンドの解決、ゲートウェイへの送信。
- ベンダーの選択、操作の実行可否、ログイン、接続先、接続状態。
- ユーザ向け設定、利用者の認証、設定の動作検証、ゲートウェイ機の再起動の依頼。

### 2.2 対象外

- VPNクライアントの直接操作とネットワークの制御。
- 複数ユーザーのアカウント管理と、複数ゲートウェイの同時管理。

## 3. 前提

- なし

## 4. 機能要件

- FR-1: 操作は、プロファイルが定義するコマンドを引数配列に解決し、選択中のベンダーのランナーへ送信して実行する。
- FR-2: Web UIから受け取る値は、プロファイルの許可条件で必ず再検証し、違反を400で拒否する。
- FR-3: 有効なベンダーの一覧と選択中のベンダーを保持して切替を受け付け、ベンダーごとの状態を独立に保持する。
- FR-4: 操作ごとの実行可否を、非対応・未ログイン・プラン制限の別と理由文で返す。
- FR-5: ログイン方式をプロファイルの宣言に従って切り替え、秘密情報は標準入力だけに渡す。
- FR-6: 接続先の一覧をCLIから都度取得し、お気に入りと最後の接続先を永続化して添える。
- FR-7: 接続と切断を制御して接続先と国を保持し、起動時に直前が接続中だった場合は同じ接続先へ再接続する。
- FR-8: ユーザ向け設定を検証して永続化し、ゲートウェイへ反映して稼働状況を中継する。
- FR-9: 単一の管理者アカウントの作成・変更・ログイン・ログアウトを提供し、状態確認・初回作成・ログイン以外の全APIで認証を要求する。
- FR-10: 設定の動作検証は、設定から導いた項目を順に1件ずつ実行し、進行と結果を取得できる。
- FR-11: ゲートウェイ機の再起動は、利用者のパスワードの再入力を条件に依頼し、結果を監査ログへ記録する。
- FR-12: プランの補足情報と、接続先を選べないプランで接続できる国・都市の参考一覧を返す。

## 5. 非機能要件

- NFR-1: ログイン状態とプランの判定のためにCLIを起動する間隔は、30秒に1回以内とする。
- NFR-2: ランナーの利用可否の確認は、並行して行い、2秒で打ち切る。
- NFR-3: 平文で保存するパスワードは0件とする。
- NFR-4: ログインの失敗は、送信元IPごとに1分あたり5回までとし、超過を429で拒否する。
- NFR-5: 監査ログと応答に含まれるパスワードと2段階認証コードは0件とする。
- NFR-6: 動作検証の結果は、直近5件までをメモリにだけ保持する。
- NFR-7: ゲートウェイとの通信で、証明書の検証を省略する経路は0個とする。
- NFR-8: ユーザ向け設定は、10秒周期でゲートウェイへ再通知する。

## 6. 受け入れ条件

- AC-1 (FR-1): 接続の操作は、プロファイルのコマンドを引数配列に解決し、選択中のベンダーのランナーへ送る。`tests/apiserver/operations.test.ts`
- AC-2 (FR-1): シェルのメタ文字を含むユーザー名は、分割も解釈もされず1つの引数として送られる。`tests/apiserver/operations.test.ts`
- AC-3 (FR-2): 一覧に存在しない接続先と不正な本文は400で拒否され、接続のコマンドはゲートウェイへ送られない。`tests/apiserver/operations.test.ts`
- AC-4 (FR-3): 有効なベンダーの一覧に選択中が示され、切り替えてもベンダーごとのお気に入りが保たれる。`tests/apiserver/providers.test.ts`
- AC-5 (FR-3): 切替時は接続中なら先に切断し、切断に失敗すると切り替えず、利用不可のランナーへは切り替えない。`tests/apiserver/providers.test.ts`
- AC-6 (FR-4): 未ログインの間は接続先を使う操作が未ログインの理由で不可となり、ログイン後は可となる。`tests/apiserver/capabilities.test.ts`
- AC-7 (FR-4): プラン制限を示す失敗は403で通知され、以後その操作がプラン制限の理由で不可となる。`tests/apiserver/capabilities.test.ts`
- AC-8 (FR-5): 資格情報入力型のログインは、パスワードと2段階認証コードを標準入力にだけ渡す。`tests/apiserver/login.test.ts`
- AC-9 (FR-5): URL提示型のログインは、認証用のURLを応答で返す。`tests/apiserver/login.test.ts`
- AC-10 (FR-6): 接続先の一覧は応答時間の昇順で、お気に入りと最後の接続先の別を含む。`tests/apiserver/operations.test.ts`
- AC-11 (FR-6): お気に入りの登録と解除は何度行っても結果が同じで、保存され、不正なIDは400になる。`tests/apiserver/operations.test.ts`
- AC-12 (FR-7): 接続後の状態は接続先と国を返し、切断で消え、最後の接続先は切断後も残る。`tests/apiserver/operations.test.ts`
- AC-13 (FR-7): 直前が接続中だった場合の起動時の復元は同じ接続先へ接続し、切断中だった場合は何もしない。`tests/apiserver/operations.test.ts`
- AC-14 (FR-8): 設定の更新は、形式不正を400で拒否し、受理した設定をゲートウェイへ通知する。`tests/apiserver/settings.test.ts`
- AC-15 (FR-8): 稼働状況はゲートウェイの応答を中継し、ゲートウェイに到達できないときは502になる。`tests/apiserver/settings.test.ts`
- AC-16 (FR-9): アカウントの作成前は初回作成だけが認証なしで使え、作成後は認証のないAPIが401になり、ログイン後に使える。`tests/apiserver/operator.test.ts`
- AC-17 (FR-9): ユーザー名とパスワードの変更は、現在のパスワードが一致するときだけ受理される。`tests/apiserver/operator.test.ts`
- AC-18 (FR-10): 動作検証は設定から導いた項目を順に実行し、同時に1件までで、結果を取得できる。`tests/apiserver/verification.test.ts`
- AC-19 (FR-11): 再起動の依頼は、パスワードが正しいときだけゲートウェイへ伝わり、誤ると401で伝わらない。`tests/apiserver/verification.test.ts`
- AC-20 (FR-12): プランの補足情報が、ログイン状態の応答のプランに含まれる。`tests/apiserver/capabilities.test.ts`
- AC-21 (FR-12): 接続先を選べないプランでは、サーバ一覧から国と都市だけの参考一覧が返る。`tests/apiserver/capabilities.test.ts`
- AC-22 (NFR-1): 実行可否を続けて取得しても、判定のCLIは30秒に1回しか起動されない。`tests/apiserver/capabilities.test.ts`
- AC-23 (NFR-2): 応答の遅いランナーがあっても、ベンダーの一覧は2秒台で返り、そのベンダーは利用不可と示される。`tests/apiserver/providers.test.ts`
- AC-24 (NFR-3): 保存されたアカウントにパスワードの平文が含まれず、ハッシュ方式が記録される。`tests/apiserver/operator.test.ts`
- AC-25 (NFR-4): ログインの失敗が5回を超えると、正しい資格情報でも429で拒否される。`tests/apiserver/operator.test.ts`
- AC-26 (NFR-5): ログインを行った後の監査ログと、CLIが秘密情報を出力した失敗の応答に、秘密情報が含まれない。`tests/apiserver/login.test.ts`
- AC-27 (NFR-6): 動作検証の結果は直近5件だけが取得でき、保存先に検証結果のファイルが作られない。`tests/apiserver/verification.test.ts`
- AC-28 (NFR-7): 別の認証局の証明書を持つゲートウェイとは通信せず、502で失敗する。`tests/apiserver/gateway-tls.test.ts`
- AC-29 (NFR-8): 起動したAPIサーバは、既定で10秒後にもう一度、設定をゲートウェイへ通知する。`tests/apiserver/settings.test.ts`
