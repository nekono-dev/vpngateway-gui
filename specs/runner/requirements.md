# SPEC-RUNNER: ランナーコンテナ要件定義

サービス全体設計（../design.md）で定義されたランナーコンテナ（`runner-<ベンダー>`）の要件を示す。Web UIから使うVPNベンダーを選べるようにするため（../requirements.md「VPNベンダーの選択（Web UI）」）、従来の「ベンダーごとに別のproxyコンテナ」から、**ベンダーCLIの実行だけを担うランナー**を切り出した（Phase 8）。ネットワーク制御（透過ゲートウェイ・Kill Switch・明示的プロキシ・接続監視）はネットワークコンテナ（`proxy`。../proxyserver/requirements.md）の責務であり、ランナーは関与しない。

# 責務の範囲

- そのベンダーのVPNクライアントCLI（AdGuard VPN CLI / Proton VPN CLI / NordVPN CLI等）の実行環境を提供し、APIサーバからの解決済みコマンドの実行要求を受理して実行する（結果は`exitCode`・標準出力・標準エラーで返す）。ベンダーごとに1つのランナーがあり、有効化されたベンダーの分だけ起動する。
- CLIが特殊な実行環境（Proton VPN CLIのNetworkManager・Secret Service・D-Bus等）を必要とする場合、その環境を**ランナーのコンテナ内で用意**する（ホストへの導入を要求しない）。他のベンダーのランナー・ネットワークコンテナの実行環境に影響しない。
- ベンダーCLIが確立するトンネルを、ゲートウェイ（ホスト）のネットワーク名前空間に作る（透過ゲートウェイ・明示的プロキシがそのトンネルを使うため）。
- 標準入力の受け渡し（ユーザー名・パスワード入力型のログイン用）に対応し、その内容をログへ残さないこと。
- 利用可否をAPIが確認できること（`GET /health`）。起動していない・応答しないランナーのベンダーは、APIが「利用不可」として扱い、選択できない。
- ベンダーごとのログイン情報（例: AdGuard VPNの認証情報、Proton VPNのkeyring）を、コンテナを再作成しても失われないよう永続化する。ベンダーを切り替えても、他のベンダーのログイン情報は失われない。

# 実行の安全性

- **自分のベンダーのバイナリ以外を実行しないこと。** 複数のランナーが同時に動いていても、あるランナーを経由して別ベンダーのバイナリや任意のコマンドを実行できない。APIコンテナが侵害・バグ混入した場合でも、ランナーが任意コマンド実行の踏み台にならない（管理者向け設定・ユーザ向け設定とは独立した、ランナー内部のセキュリティ機構）。
- コマンドはシェルを経由せずに実行する（引数にシェルメタ文字が含まれても解釈されない）。
- パスワード等の秘密情報（標準入力）を、ログ・エラー応答に残さない。
- 内部専用HTTPサーバは、コンテナ外部（LAN含む）から一切到達不能であること（UDS。../design.md）。

# 権限に関する制約

- 必要以上の権限を与えないこと。`privileged: true`は使用しない。`network_mode: host`・`cap_add: [NET_ADMIN]`・`/dev/net/tun`（トンネル確立に必要）で不足する場合のみ、実装時のPoCで個別に追加検討する。
- CLIやその実行環境の起動にroot権限が必要な場合（例: NetworkManager）でも、ランナー本体・CLIの実行は非root（`vpngwgui`）で行う。

# ベンダーCLIとの関係

- **ベンダーCLI独自のKill Switch・経路制御**（Proton VPN CLIの`kill-switch`等）は使わず、本システムのnftablesによるKill Switch・透過ゲートウェイに一本化する（二重の遮断規則による競合・切断後の通信不能を避ける）。
- ベンダーの追加は、**ベンダーバンドル（`vendors/<ベンダーID>/`。ランナーのイメージ・composeのfragment・永続化ボリューム・プロファイル・必要ならホスト側の追加手順。`../design.md`「ベンダー非依存の設計原則」）の追加だけ**で対応でき、APIサーバ・Webサーバ・ネットワークコンテナ・composeの本体・共通インストーラの改修を要求しない（Phase 10）。
- ランナーの実行部（`proxy/src`の`runner.ts`等）は、ベンダーの名前・CLIの書式を持たない。ベンダーを知るのは`RUNNER_ALLOWED_BINARY`（許可するバイナリ1つ）だけである（Phase 10）。

# 対象外

- 透過ゲートウェイ・Kill Switch・明示的プロキシ・トンネル検出・接続監視（ネットワークコンテナの責務）。
- 複数ベンダーの同時接続（接続は常に1ベンダー。切替はAPI・Web UIの責務。../requirements.md）。
