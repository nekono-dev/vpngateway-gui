# システムの目的

AdguardVPNやNordVPNをLinuxサーバ上にインストールし、VPNゲートウェイとして構築する構成において、Linux上でCLI入力する手間を省くため、Webアプリケーションとして代用できるようにする。

# システム要件

OSは以下に対応する。

- Debian（RaspberryPiOS）
- Ubuntu（24.04 LTSなど）

# システムの互換性

このシステムはベンダロックインを防ぐため、各社CLIの操作内容をサーバ管理者が指定する。つまり、いくつかの実施可能な操作に対して、実行するコマンドを管理者自身が設定する。ex: VPNに接続するコマンド「adguardvpn-cli connection」
一部のコマンドについては、プレースホルダーに対応する。 ex: VPNの接続先を変更する「adguardvpn-cli connection -l %COUNTRY%」

これらの設定は、責務の異なる2種類の設定として明確に分離する必要がある。

- **管理者向け設定（VPNクライアント操作プロファイル）**: サーバ管理者が作成し、プロキシサーバ上で実行するVPNベンダーCLIのコマンド体系（プレースホルダー含む）を定義する。エンドユーザー（Web UI利用者）は変更できない。
- **ユーザ向け設定**: Web UI利用者がGUIから変更できる運用設定。例: VPNトンネルを経由させない宛先ドメインを指定する「VPN除外設定（split-tunnel）」、Kill Switch（後述）のON/OFF、お気に入りの接続先、プロキシモード（透過ゲートウェイ／明示的SOCKS5・HTTPプロキシ）の切替。APIサーバが受理し永続化する。

接続先（VPNサーバの所在地）は、VPNベンダーCLIが返す接続可能な一覧（国・都市・ping値）を都度取得して利用者に提示する。管理者向け設定に接続先の一覧を静的に持たない（ベンダー側のサーバ増減で陳腐化するため）。最後に接続した接続先は、システムが記憶して次回の既定選択に用いる（利用者が設定する項目ではない）。

「ホストの変更を最小限に抑える」とは、ホストを一切変更しないという意味ではなく、**ホスト側で変更するファイル数を最小限にする**という意味である。

# 認証・認可

現時点ではWeb UI／APIサーバへの認証機構を設けない。LAN内限定での利用を前提とする。
