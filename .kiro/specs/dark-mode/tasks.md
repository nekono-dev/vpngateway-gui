# Implementation Plan

- [x] 1. API の表示設定の土台を作る
- [x] 1.1 テーマの値の形を定める
  - テーマの値は「OS 規定」「ライト」「ダーク」の3種類に限られ、それ以外は受け付けない形として定める
  - 取得の応答と保存の要求は、どちらも theme だけを持つ同じ形を使う
  - 完了条件: 3種類の値は形の検査を通り、それ以外の値は検査で拒否される
  - _Boundary: UiPreferences schema_
  - _Requirements: 2.4, 2.5, 3.2_

- [x] 1.2 表示設定を状態ディレクトリへ保存・読み込みする
  - 保存先は状態ディレクトリ配下の表示設定ファイルとし、場所は既存の状態ディレクトリの設定に従う
  - 未保存のときと、読めない・壊れている・値が不正なときは、「OS 規定」を返し、例外を上位へ投げない
  - 保存した値は、読み直すと同じ値が返る
  - 完了条件: 単体テストで、未保存・保存と読み直し・破損ファイル・不正値の4つが期待どおりの値になる
  - _Boundary: UiPreferences store_
  - _Requirements: 2.1, 2.6_

- [x] 2. API の取得と保存のルートを作る
- [x] 2.1 テーマの取得（公開）と保存（管理者のみ）のルートを登録する
  - 取得は未ログインでも呼べ、応答は theme だけを含む
  - 保存は管理者のログイン済みセッションがある要求だけ受け付け、未ログインの保存は保存せず認証が必要な応答を返す
  - 保存した値は次の取得に反映される
  - 完了条件: 認可の例外に取得だけが加わり、保存は既存の認可で保護されている
  - _Boundary: UiPreferences route_
  - _Requirements: 2.1, 2.2, 3.1, 3.2, 3.3, 7.1, 7.2_

- [x] 2.2 取得と保存のルートの統合テストを書く
  - 未ログインの取得は成功し、応答に theme 以外の項目を含まない
  - 未ログインの保存は認証が必要な応答となり、保存された値は変わらない
  - ログイン済みの保存は値を保存し、次の取得で同じ値が返る
  - 3種類以外の値の保存は入力の誤りとして拒否され、保存された値は変わらない
  - 完了条件: これら4つのケースを含む統合テストが合格する
  - _Boundary: UiPreferences route_
  - _Requirements: 2.1, 2.2, 2.5, 3.1, 3.2, 3.3, 7.1, 7.2_

- [x] 2.3 生成クライアントを更新し、取得と保存の関数を使えるようにする
  - API の公開情報を書き出し、web の生成クライアントを作り直す
  - 生成された取得と保存の関数が、テーマの値の形で型付けされている
  - 完了条件: 生成の後に web の型検査が通り、取得と保存の関数を web から呼べる
  - _Boundary: generated API client_
  - _Depends: 2.1_
  - _Requirements: 2.1, 3.1_

- [x] 3. テーマの判定と適用（web の純粋な処理）
- [x] 3.1 (P) 循環・解決・表示名・theme-color の値を定める
  - 切り替えの順序は「OS 規定 → ライト → ダーク」の循環とする
  - OS 規定は、OS の配色がダークならダーク、そうでなければライトに解決する
  - 表示名と theme-color の値を定める。ライトの theme-color は現行の値を保ち、ダークは設計で定めた値を使う
  - 完了条件: 単体テストで、循環の3段階、解決の4通り、表示名と theme-color の値が確認できる
  - _Boundary: theme-preference_
  - _Requirements: 1.1, 1.3, 6.2_

- [x] 3.2 解決後のテーマを画面の属性と theme-color に反映する
  - 解決したテーマを画面全体の属性に書き、ライトとダークの切り替えを画面に反映する
  - theme-color の値を解決後の値に書き換える。対応する要素が無い場合は何もしない
  - 完了条件: 単体テストで、ダークとライトの切り替えで属性と theme-color が変わり、要素が無くても例外にならない
  - _Boundary: apply-theme_
  - _Depends: 3.1_
  - _Requirements: 1.2, 4.3, 6.1_

- [x] 4. 色の変数化
- [x] 4.1 (P) 色を変数に一本化し、両テーマの値を定める
  - スタイル内に直接書かれた色を、定めた変数へすべて置き換える
  - ライトの見た目は現行と変わらない（変数のライトの値は現行の色と一致する）
  - ダークの値を定義し、本文の文字・状態の色・枠線が背景と見分けられる値にする
  - フォーム部品とスクロールバーもダークに揃える
  - 完了条件: 直接の色指定が残っていないこと、ライトの見た目が変わらないことを、画面確認（7.2）で確かめられる
  - _Boundary: styles_
  - _Requirements: 5.1, 5.2, 5.3, 5.4_

- [x] 5. テーマの状態の管理（Provider）
- [x] 5.1 起動時の取得と OS 配色への追従を実装する
  - 取得が終わるまで子要素を描画せず、画面は空白にする
  - 取得した値を画面に適用してから子要素を描画する
  - 取得が失敗した、または応答が不正なときは「OS 規定」で描画を続ける
  - OS の配色が変わると、「OS 規定」の表示が再読み込みなしで変わる
  - 完了条件: 単体テストで、取得中の空白、取得後の適用、失敗時の既定、配色変化への追従が確かめられる
  - _Boundary: ThemeProvider_
  - _Depends: 2.3, 3.2_
  - _Requirements: 1.2, 1.4, 2.2, 3.1, 3.4, 4.1, 4.2, 4.3, 6.1_

- [x] 5.2 切り替えの保存と失敗時の差し戻しを実装する
  - 切り替えは画面へ即時に反映し、その後に保存する
  - 保存に成功したら、サーバの応答の値を保持する
  - 保存に失敗したら、切り替え前のテーマに戻し、通知を出す
  - 保存中は別の切り替えを受け付けない
  - 完了条件: 単体テストで、即時反映、保存失敗での差し戻しと通知、保存中の受け付け停止が確かめられる
  - _Boundary: ThemeProvider_
  - _Requirements: 1.2, 2.1, 2.3_

- [x] 6. 切り替えボタンと画面への組み込み
- [x] 6.1 テーマの切り替えボタンを作る
  - 表示は「テーマ: OS 規定」などの現在の選択を示す
  - 押すと次のテーマへ循環する
  - 保存中は押せない
  - 完了条件: 単体テストで、表示文言、循環、保存中の無効化が確かめられる
  - _Boundary: ThemeToggleButton_
  - _Depends: 5.2_
  - _Requirements: 1.1_

- [x] 6.2 ヘッダーにボタンを置き、Provider の順序を組む
  - ログイン後のダッシュボードのヘッダーに切り替えボタンを表示する
  - 初期設定とログインの画面には表示しない
  - Provider の順序は、通知、テーマ、認証、画面の順とし、テーマの取得が終わるまで認証の画面も描画しない
  - 完了条件: ダッシュボードのヘッダーでボタンが見え、ログイン前の画面には無い。既存の単体テストが通る
  - _Boundary: App header, entry wiring_
  - _Depends: 6.1, 5.2_
  - _Requirements: 1.5, 4.1_

  - 切り替えボタンで循環し、押した直後に反映される
