# Requirements Document

## Project Description (Input)
- **誰が問題を抱えているか**: ping を計測できないプロバイダ（現在は ProtonVPN。`features.locationPing=false`）を使い、接続先を選ぶ利用者。
- **現状**: 接続先の一覧に遅延の目安が無く、既定の順（国名順）のままになっている。国・都市の座標と、利用者の場所は、アプリに無い。
- **変えたいこと**: ping を計測できないとき、国の行と都市の行を「利用者の国の首都に近い順」に並べ、各行に距離（約 N km）を表示する。座標は、配布物に同梱した公開データ（Natural Earth）から引く。利用者の場所は、ブラウザの言語設定の地域を初期値とし、設定画面で変更できる。
- 詳細は [brief.md](brief.md) を参照。

## Introduction
ping を計測できないプロバイダで、国の行と都市の行を、利用者の国の首都からの距離の近い順に並べ、各行に距離を表示する。距離は、利用者の国の首都から、各行の国の首都または都市までの大圏距離（地球表面の最短距離）で求める。座標は、配布物に同梱した公開データから引き、実行時に外部と通信しない。

## Boundary Context
- **In scope**:
  - ping を計測できないプロバイダの、国の行と都市の行の距離順への並べ替えと、各行の距離の表示
  - 利用者の場所の決定（ブラウザの言語設定の地域を既定値とし、保存された値で上書きする）と、設定画面での変更
  - 国の首都と都市の座標の参照（配布物に同梱した公開データから）  - プランで接続できる接続先の参考一覧への、同じ規則の適用
- **Out of scope**:
  - ping を計測できるプロバイダの並べ替え（従来どおり ping の順）
  - サーバの一覧の並べ替え（従来どおり Score の順。距離は使わない）
  - 都市を基点にした距離（距離の基点は、利用者の国の首都だけ）
  - サーバ負荷の表示、GeoIP などによる利用者の場所の自動推定、接続・切断の処理、プラン制限の判定、ping 計測の変更
- **Adjacent expectations**:
  - 国の一覧（国コードと国名）と、都市の一覧（国コード・国名・都市名）は、既存の取得の結果を使う。都市の一覧は `location-city-selection` が提供する。
  - ping を計測できるかどうかの判定は、既存の判定結果を使う。
  - 実行時に外部の通信先へ送る情報はない。利用者の場所も、一覧の内容も送らない。

## Requirements

### Requirement 1: 距離順に並べる条件
**Objective:** As a 利用者, I want ping が分からない接続先でも自分に近い国と都市が先に並ぶこと, so that どの接続先を選ぶかを判断できる

#### Acceptance Criteria
1. When 有効な VPN プロバイダが ping の計測に対応しておらず、かつ利用者の場所が決まっているとき, the system shall 国の一覧を、利用者の国の首都からの距離の近い順（近いものを先頭）に並べる。
2. When 有効な VPN プロバイダが ping の計測に対応しておらず、かつ利用者の場所が決まっているとき, the system shall 都市の一覧を、利用者の国の首都からの距離の近い順（近いものを先頭）に並べる。
3. While 有効な VPN プロバイダが ping の計測に対応しているとき, the system shall 国の一覧と都市の一覧を従来どおり ping の値の順に並べ、距離の順は適用しない。
4. Where 都市の一覧にお気に入りの都市があるとき, the system shall お気に入りの都市を都市の一覧の先頭に置き、その相対的な順序を保ち、残りの都市を距離の順に並べる。
5. If 二つの接続先の距離が同じ場合, then the system shall 両者の既存の相対的な順序を保つ。
6. If 接続先に距離が決まっていない場合, then the system shall その接続先を、距離が決まっているすべての接続先の後ろに置き、その中の既存の順序を保つ。

### Requirement 2: 利用者の場所の決定
**Objective:** As a 利用者, I want 初期設定をしなくてもおおよその場所を基準に並ぶこと, so that 設定の手間なく近い接続先が先に見える

#### Acceptance Criteria
1. While 利用者に保存された場所があるとき, the system shall 保存された場所を利用者の場所として使う。
2. While 保存された場所がないとき, the system shall ブラウザの言語設定のうち、地域を含む最初の言語の地域を、既定の利用者の場所として使う。
3. If 保存された場所がなく、かつブラウザの言語設定に地域が含まれない、または決まった国が既知の国でない場合, then the system shall 距離の順を適用せず、既存の順序を保つ。

### Requirement 3: 国の首都と都市の座標の参照
**Objective:** As a 運用者, I want 距離の計算に必要な座標を、外部の取得や手作業の表なしで得ること, so that 座標の取得の失敗や、外部への情報の送信を心配せずに済む

#### Acceptance Criteria
1. When 利用者の国、または接続先の一覧にある国の首都の座標を求めるとき, the system shall 配布物に同梱した公開データから、その国の首都（公開データの「Admin-0 capital」の区分）の座標を引く。首都の区分が一国に複数ある場合は、人口の最も多い首都の座標を使う。首都の区分が無い国は、Requirement 3-5 の扱いとする。
2. When 都市の一覧にある都市の座標を求めるとき, the system shall 配布物に同梱した公開データから、国コードと都市名が一致する都市の座標を引く。都市名は、公開データの名称・英語名・ASCII 名のいずれかと照合する。
3. Where 国コードと都市名が一致する都市が同じ国に複数あるとき, the system shall 人口の最も多い都市の座標を使う。
4. The system shall 座標を配布物に同梱し、実行時に外部から取得しない。
5. If 同梱の公開データに、接続先の国の首都または都市の座標が無い場合, then the system shall その接続先を距離なしで表示し、既存の順序を保つ。
6. If 利用者の場所の座標が得られない場合, then the system shall すべての接続先について既存の順序を保ち、距離を表示しない。
### Requirement 4: 距離の計算と表示
**Objective:** As a 利用者, I want 各接続先までのおおよその距離を一目で知ること, so that 近さを数字で比べられる

#### Acceptance Criteria
1. The system shall 利用者の国の首都と、国の一覧の各国の首都の間の距離を、大圏距離（地球表面上の最短距離）として計算する。
2. The system shall 利用者の国の首都と、都市の一覧の各都市の間の距離を、大圏距離として計算する。
3. When 接続先の距離が決まったとき, the system shall その接続先の行に「約 N.Yk km」と表示する。千 km 単位の値を小数点以下第一位まで表示する（例: 「約 2.1k km」）。
4. If 接続先の距離が決まらない場合, then the system shall その接続先の行に距離を表示しない。

### Requirement 5: プランの参考一覧への適用
**Objective:** As a 利用者, I want プランで接続できる接続先の参考一覧も同じ基準で近い順に見ること, so that プランの範囲を、自分の場所から見て判断できる

#### Acceptance Criteria
1. Where 有効な VPN プロバイダが ping の計測に対応していないとき, the system shall プランで利用できる接続先の参考一覧を、利用者の国の首都からの距離の近い順に並べる。Requirements 1 から 4 と同じ規則を使う。
2. If プランの参考一覧の項目に距離が決まらない場合, then the system shall その項目を距離が決まっている項目の後ろに置き、距離を表示しない。

### Requirement 6: 設定画面での利用者の場所
**Objective:** As a 運用者, I want 利用者の場所を既定値とは別の国に設定し、既定値へ戻すこと, so that 既定値が今いる場所と違う場合でも正しい順に並べられる

#### Acceptance Criteria
1. The settings dialog shall 運用者に、すべての国の中から利用者の国を選ばせる。
2. When 運用者が国を保存したとき, the system shall その国をサーバに保存し、次の要求から接続先の一覧とプランの参考一覧に適用する。
3. When 運用者が既定値に戻すを選んだとき, the system shall 保存された場所を削除し、Requirement 2 で定めた既定の利用者の場所を使う。
4. While 既定の利用者の場所が使われているとき, the settings dialog shall 現在の利用者の場所を、「既定値はブラウザの言語設定から推定したもので、現在の場所と異なる場合があります」という注記とともに表示する。
5. If 運用者がログインしていない場合, then the system shall 利用者の場所の変更を拒否する。

## 決定事項と前提
- 距離の基点は、利用者の国の首都に限る（都市を基点にした距離は行わない）。国の行と都市の行は、この基点からの距離で並べる。
- 座標のデータ源は Natural Earth（populated places）とする。利用者の選択による。
  - 理由: アカウントが不要で、パブリックドメインで提供され、同梱できる。実行時に外部へ情報を送らない。
  - 公式の利用条件では、帰属表示は不要とされている。
  - GeoNames は採らない（利用者にアカウントとユーザー名の用意を求めるため。利用者の選択による）。
- 同名の都市の扱い: 人口の最も多い都市を選ぶ（Requirement 3-3）。Natural Earth 5.1.2 の populated places に人口（POP_MAX）の属性があることを、公式の資材で確認済み（research.md）。
- 都市名の一致は、国コードと都市名の完全一致とする（表記の揺れは扱わない。取りこぼしは Requirement 3-5 の扱いになる）。
- 都市の一覧の入力（国コード・国名・都市名）は、`location-city-selection` の要件と揃える。

## 承認の前提
- 検証済み（research.md）: ProtonVPN の都市 196 件のうち 192 件が一致した（98%）。取りこぼしは 4 件（Novi Travnik・Schaan・Ashburn・Secaucus）で、公開データに存在しない。これらは Requirement 3-5 により距離なしで表示する。
- 決定（2026-11-08）: 首都が一国に複数ある国（ボリビア・コートジボワール・ミャンマー・パレスチナ・南アフリカ）は、人口の最も多い首都を使う（Requirement 3-1）。首都の区分が無い国（プエルトリコ）は、距離なしで表示する（Requirement 3-5）。
- 本 spec の承認は、`location-city-selection` の要件 7-3・7-4 の確認より先に行う。
