# Brief: location-distance-sort

## Problem
ping を計測できないプロバイダ（現在は ProtonVPN。`features.locationPing=false`）では、接続先の一覧に遅延の目安が無い。
利用者は、どの接続先が近いかを判断できず、一覧は既定の順（国名順）のままになる。

## Current State
- ping の可否は、capability `pingMeasurement` で判定している。ProtonVPN は非対応（理由文は「このVPNプロバイダでは ping 計測を利用できません」）。
- 接続先の一覧は CLI の `countries list` 由来で、国単位（国名とコード）のみを持つ。座標は無い。
- 都市の一覧は `location-city-selection` で追加する（ProtonVPN は国ごとに取得し保存する）。都市の座標は、まだ無い。
- 利用者の所在地を表すデータは、アプリに無い。構成に CDN が無く、位置を示すヘッダは付かない。
- 2026-11-08 の目視確認: 有料版では全接続先が表示され、任意の接続先に接続できた。ping 一覧は出ず、理由文は修正済み。

## Desired Outcome
ping を計測できないとき、接続先の一覧（国の行と都市の行）は「利用者の場所に近い順」に並ぶ。
- 近さは、利用者の国の首都から、各接続先（国の首都、または都市）までの大圏距離（地球表面の最短距離）で決める。
- 座標は、配布物に同梱した公開データ（Natural Earth）から引く。実行時に外部と通信しない。
- 利用者の場所は、ブラウザの Accept-Language の地域を初期値とし、設定画面で変更できる。変更した値はサーバ側に保存する。

## Approach
- **採用**: API 側で、国の首都と都市の座標を同梱データから引き、大圏距離（Haversine 式）を純粋関数で計算する。並べ替えた一覧を API が返す。
  - 国の行は、国の首都の座標と利用者の国の首都の距離で並べる。
  - 都市の行は、都市の座標と利用者の国の首都の距離で並べる（基点は国単位のまま）。
  - 利用者の場所は、リクエストの Accept-Language（地域サブタグ。例: `ja-JP` → `JP`）を既定値にし、設定 API で上書きされたらその値を使う。
- **採用（座標のデータ源）**: Natural Earth（populated places）。アカウント不要・パブリックドメイン・同梱可能で、実行時の外部通信が要らない。
  - 都市の一致は、国コードと都市名の完全一致。同名が複数あるときは、人口の最も多い都市を使う。
  - 件数と属性（人口・国コード・緯度経度）は、公式の資材（dbf）で確認済み（7,342 件。詳細は research.md）。
- **不採用**: GeoNames。ユーザー名（アカウント）の用意が利用者の手間になるため（利用者の判断により見送り）。
- **不採用**: Wikidata（CC0 で、アカウント不要だが、都市ごとに外部へ問い合わせ、都市名を送るため。今回は同梱方式を優先）。
- **不採用**: GeoIP（公開 IP から所在地を推定）。外部のデータベースか外部通信が要り、利用者の情報の送信の検討が必要になるため。
- **不採用**: ブラウザ側だけで並べ替える。並べ替えの規則が API とずれるおそれがあり、保存した設定と一致させにくいため。

## Scope
- **In**:
  - 国の首都と都市の座標の参照（配布物に同梱したデータから）
  - 大圏距離の計算（純粋関数）
  - 利用者の場所の決定（Accept-Language の既定値、保存された設定での上書き）
  - ping を計測できないときの並べ替え（国の行・都市の行）と、各行への距離（km）の表示
  - 利用者の場所を設定する画面（設定ダイアログの新しいタブ）と、その保存・取得の API
  - プランで接続できる接続先の参考一覧への、同じ規則の適用
- **Out**:
  - 接続先の負荷（サーバ負荷）の表示（利用者の判断により対象外）
  - ping 計測の変更、CLI の呼び出しの追加
  - 都市の一覧そのもの（取得・保存・表示。`location-city-selection` で扱う）
  - GeoIP などによる自動の所在地の推定
  - 都市の位置を基点にした距離（基点は利用者の国の首都）
  - 外部からの座標の取得・更新（座標は配布物に含まれる）

## Boundary Candidates
- 同梱データの読み込みと座標の参照（国の首都と都市）
- 大圏距離の計算と並べ替え（純粋関数。外部に依存しない）
- 利用者の場所の決定（Accept-Language の既定値と、保存された設定）
- 一覧の距離の表示（ping 非対応のときだけ）
- 設定画面（利用者の場所の入力と保存）

## Out of Boundary
- 負荷の表示、ping 計測、接続・切断の処理、プラン制限の判定（既存の capability の仕組みをそのまま使う）
- 都市の一覧の取得と保存（ProtonVPN の国ごとの取得）

## Upstream / Downstream
- **Upstream**:
  - 接続先の一覧（`api/src/locations/`）と、ProtonVPN の国ごとの都市の一覧（`location-city-selection` が取得・保存する）。距離の計算には、国コード・国名・都市名の組を使う。
  - capability の `pingMeasurement`（`api/src/capabilities/`）、設定の保存（既存の ui-preferences と同様の保存の仕組み）。
- **Downstream**: `location-city-selection`（都市の行の並べ替えに、この spec の並べ替えを使う）。

## Existing Spec Touchpoints
- **Extends**: なし（既存の spec は、接続先の一覧を扱っていない）。
- **Adjacent**:
  - `location-city-selection`: 都市の一覧と都市の行。並べ替えの呼び出しは、そちらの一覧から行う。両 spec で、入力（国コード・国名・都市名）と出力（並べ替えた順序・距離）の形を揃える。
  - `vendor-live-e2e`（実機の試験。接続先の一覧の並べ替えは対象外）、`e2e-tests`（API クライアントの型を共有する）。

## Constraints
- 実行時に外部へ送る情報はない。利用者の場所も、一覧の内容も送らない。
- 座標のデータは配布物に含め、実行時に外部から取得しない。
- 既定値（Accept-Language）は、言語の設定から推定するもので、今いる場所とは限らない。画面にその旨を注記する。
- ProtonVPN CLI 1.0.5 の出力に依存する部分（一覧の国コードと都市名）は、既存の samples.json で検証する。
- 都市名の取りこぼし（表記の違い）は、同梱データとの照合で確かめる。取りこぼしが多い場合は、一致の規則を見直す。

## 未確定の前提（要件・設計で確認する）
- 並べ替えは、ping を計測できないプロバイダ（現在は ProtonVPN）のときだけ行う。ping を計測できるときは、従来どおり ping の順。
- お気に入りの都市は、都市の一覧の先頭に置く。その下を距離の順にする（要件 1-4）。
- 距離は、一覧の各行に「約 N.Yk km」として表示する（千 km 単位・小数点以下第一位まで）。
- 同名の都市が同じ国に複数ある場合は、人口の最も多い都市の座標を使う（2026-11-08 に決定。人口の属性は公式データで確認済み）。
- 国の首都が一国に複数ある場合（ボリビア・コートジボワール・ミャンマー・パレスチナ・南アフリカ）は、人口の最も多い首都を使う（2026-11-08 に決定）。首都の区分が無い国（プエルトリコ）は、距離なしで表示する（2026-11-08 に決定）。
- Natural Earth の件数・属性・ProtonVPN の都市名の取りこぼしは、承認の前提として確認する（要件の「承認の前提」を参照）。
