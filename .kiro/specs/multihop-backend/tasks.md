# Implementation Plan

- [x] 1. 基盤: 型・プロファイル宣言
- [x] 1.1 多段接続の型とスキーマを定める
  - 経路の指定（出口と段ごとの指定）のスキーマを定め、手動選択の接続先の有無を型で強制する
  - 完了条件: 有効な指定と無効な指定（手動選択なのに接続先がない、接続先の指定が手動以外にある、切断時の動作が範囲外）をテストで判別できる
  - _Requirements: 1.1, 1.5, 2.3, 3.1_

- [x] 1.2 ベンダーの宣言に段の選び方を追加する
  - プロファイルのスキーマに `hopSelection`（比較する値・最小化）を追加し、AdGuard VPN は ping の最小、ProtonVPN は `VPN/serverlist.json` の Score の最小を宣言する
  - 未ログインの判定は、既存の `account.notLoggedInPattern` を使う（新しい宣言は追加しない）
  - 完了条件: 両プロファイルが読み込めて、宣言の欠落や不正な値はテストで拒否される
  - _Requirements: 2.2, 7.2_

- [ ] 2. 候補の値とログイン確認
- [ ] 2.1 (P) 候補の一覧に ping と Score の値を付ける
  - 既存の一覧の取得を拡張し、AdGuard VPN の ping と ProtonVPN の Score を候補ごとに付ける
  - Score は既存の `availableLocations` と同じ読み取り専用の経路で `VPN/serverlist.json` から読み、API で結果を保持して、キャッシュの更新時刻が変わったときだけ読み直す
  - 完了条件: 候補が提供元ごとに得られ、候補が空の提供元は空として返される。キャッシュの更新時刻が変わるまで読み直さないことをテストで確かめる
  - _Boundary: LocationCatalog_
  - _Requirements: 2.2, 2.6, 3.3_

- [ ] 2.2 (P) 段ごとのログイン状態を、既存の判定で確かめる
  - プロファイルの `account.notLoggedInPattern` を使い、出力が未ログインの文言に一致したとき、その段のログインが失われていると判定する
  - 完了条件: AdGuard VPN の `Please log in` / `not logged in`、ProtonVPN の `Authentication required` の出力で、判定が未ログインになる
  - _Boundary: LoginCheck_
  - _Requirements: 7.2_

- [x] 3. 計画と選択（純粋な計算）
- [x] 3.1 (P) 段ごとの接続先の選び方を実装する
  - ランダム（乱数を注入）、プロバイダ選択（提供元の規則。既定の提供元は出口と同じ）、手動選択を実装する
  - ランダムとプロバイダ選択の結果は読み取り専用として返し、選び方を変えたら決め直す
  - 完了条件: 乱数を固定したテストで、各選び方の結果が一致し、既定の提供元が出口と同じになる
  - _Boundary: HopSelector_
  - _Requirements: 2.1, 2.2, 2.3, 2.4, 2.5, 2.7_

- [x] 3.2 経路の計画を作る
  - 段の指定を、外段から並んだ計画に変換する。段数 1 は出口だけの計画になる
  - 段ごとの切断時の動作を計画に保持し、候補なし・提供元のプラン・ログイン喪失・規則なしを、段の位置つきのエラーで返す
  - 完了条件: 段数 1 と段数 3 の計画が、外段から内段の順で得られ、各エラーが段の位置とともに返される
  - _Requirements: 1.1, 1.3, 1.4, 1.5, 2.6, 3.3, 4.3, 7.2_

- [ ] 4. 出口コンテナ方式（ゲートウェイと出口・中継コンテナの規則）
- [ ] 4.1 (P) 出口コンテナ内の NAT と Kill Switch の規則を生成する
  - 出口コンテナ内で、ゲートウェイからの転送を自分のトンネル経由の外向きだけに許可し、トンネルを経由しない外向き通信を遮断する規則を生成する（純粋関数）
  - 完了条件: 生成した規則が、トンネル以外への外向きの許可を含まないことをテストで確かめる
  - _Boundary: ExitContainerRules_
  - _Requirements: 4.1, 6.1_

- [ ] 4.2 (P) 中継コンテナ内の段ごとの NAT・既定経路・切断時の動作を生成する
  - 中継コンテナ内で、内側の段の通信を自分のトンネル経由で外側へ送る規則と、既定経路の向きを生成する。切断時の動作が `dropHop` の段は、経路から外して残りへ向け直す規則を生成する
  - 完了条件: 段数に応じた規則が生成され、`dropHop` の段の切断で外側への既定経路が残りの段へ向け直される規則になる
  - _Boundary: RelayRules_
  - _Requirements: 1.1, 4.2, 6.1_

- [ ] 4.3 (P) LAN から出口コンテナへの転送規則（ホスト側）を生成する
  - ゲートウェイで、LAN の通信を出口コンテナのネットワークへ転送する規則を生成する。出口コンテナが使えない、または構築中は、LAN の通信を全て遮断する規則を生成する（fail closed）
  - 完了条件: 遮断の規則と通過の規則が切り替わり、遮断の規則では LAN からの通信が全て落ちることをテストで確かめる
  - _Boundary: ExitGateway_
  - _Requirements: 4.1, 4.4, 4.5, 6.1_

- [ ] 4.4 (P) 経路の実効上限を測り、出口の最大サイズを設定する
  - DF 付きの探索で経路の実効上限を測り、出口のトンネルの最大サイズを設定する。探索が得られないときは既存の値を変えない
  - 完了条件: 探索結果の解析（通った最大と通らない最小）がテストで一致し、探索失敗時に既存の値が残る
  - _Boundary: PathMtu_
  - _Requirements: 6.2, 6.3, 6.4_

- [ ] 4.5 ランナーを bridge ネットワークへ移し、規則に必要なツールを含める
  - ベンダーごとの compose で、ランナーを `network_mode: host` から専用の bridge ネットワークへ移し、イメージに nftables を含める
  - 完了条件: 両ベンダーのランナーが bridge ネットワーク上で起動し、コンテナ内で nftables が使える
  - _Depends: 4.1_
  - _Requirements: 1.1, 6.1_

- [ ] 4.6 ゲートウェイの状態を、出口コンテナ方式の転送規則へ置き換える
  - 単一の `vpnIface`（ホストのトンネル）の前提を外し、出口コンテナの状態（接続・ネットワーク）から転送規則を組み替える。明示的プロキシは本 spec で無効化する
  - 完了条件: 出口コンテナが接続するとLAN の通過が許可され、切断すると遮断に戻る。明示的プロキシが起動しない
  - _Depends: 4.3, 4.5_
  - _Requirements: 6.1, 4.1, 4.4_

- [ ] 4.7 段ごとのトンネルの状態を、問い合わせに応じて返す
  - API の問い合わせに対して段ごとのトンネルの状態を返し、切れた段の位置と状態を返す。問い合わせが失敗したときは `unknown` とする
  - 完了条件: 段の一つが切れると、その段の位置と状態が返され、問い合わせの失敗で `unknown` になる
  - _Depends: 4.6_
  - _Requirements: 4.2, 4.4, 4.5, 4.6, 5.2_

- [ ] 4.8 (P) 段の識別子つきの宛先で、段のランナーへ転送する
  - 既存の転送を拡張し、段の識別子を含む宛先（`/runners/<vendorId>/<slot>/*`）を、段のランナーの接続先へ送る
  - 完了条件: 段の識別子つきの要求が対応する段のランナーに届き、識別子のない既存の要求は今の挙動のまま動く
  - _Boundary: RunnerForward_
  - _Requirements: 1.1_

- [ ] 5. 段のデバイスとコンテナの用意
- [ ] 5.1 (P) デバイス（段）の登録情報を保存する
  - デバイスごとに提供元・MAC・ボリューム・ランナーの識別子を保存し、MAC とボリュームは登録後に変更できないようにする
  - 完了条件: 登録したデバイスの MAC とボリュームを変更しようとすると拒否され、保存した値が再起動後も残る
  - _Boundary: DeviceRegistry_
  - _Requirements: 3.1, 7.1_

- [ ] 5.2 (P) 段コンテナの用意を依頼ファイルで出し、応答を待つ
  - 依頼ファイルを一時名で書いてから改名して置き、応答を 1 秒ごとに確かめる。180 秒を超えたら `timeout` を返す
  - 完了条件: 依頼が正しい形式で置かれ、応答がない状態が 180 秒を超えると `timeout` になることをテストで確かめる
  - _Boundary: SlotRequest_
  - _Requirements: 1.2, 7.1_

- [ ] 5.3 ホストの常駐処理で段コンテナを作る・作り直す
  - 依頼を読み、MAC とボリュームを登録情報と照合し、一致しなければ `rejected` を返す。一致すれば、固定した MAC とボリュームで段コンテナを作る（既存なら作り直す）
  - 同じ requestId は二度作らない。完了は `done`、失敗は `failed` と理由を応答に書く
  - 完了条件: 同じ依頼を二度送っても、コンテナは一つだけになり、不一致の依頼は作られない
  - _Depends: 5.1, 5.2_
  - _Requirements: 1.2, 7.1_

- [ ] 5.4 常駐処理を配布し、依頼ディレクトリを接続する
  - インストーラで常駐処理を配布し、依頼と応答のディレクトリをゲートウェイのコンテナに接続する
  - 完了条件: 導入後に依頼ディレクトリが両方から見え、常駐処理の検査（`shellcheck`）が通る
  - _Depends: 5.3_
  - _Requirements: 1.2_

- [ ] 6. 経路の状態と実行（API）
- [ ] 6.1 接続状態の保存先を一つにする
  - 経路の接続状態（`ChainStatus`）を唯一の保存先にし、段数 1 の接続状態は、同じ保存先を既存の形に変換して返す
  - 完了条件: 段数 1 の状態が既存の接続状態と同じ内容で返り、段の並びが外側から内側の順に保たれる
  - _Depends: 1.1, 4.7_
  - _Requirements: 1.3, 1.5, 4.6, 5.1, 5.2, 5.3_

- [ ] 6.2 経路を外段から順に接続・切断する
  - 段ごとに、ログイン確認、段コンテナの用意、既定経路の設定、接続の順で行い、途中の段が失敗したら接続済みの段を外側から切断する
  - 全段の接続と出口の最大サイズの設定が終わるまで LAN の通信を遮断し、終わったら通過を許可する
  - 完了条件: 外段から順に接続した記録が残り、途中の失敗で接続済みの段が外側から切れ、構築中に通信が通らないことを、ProxyClient を差し替えたテストで確かめる
  - _Depends: 2.2, 3.2, 4.3, 4.4, 4.6, 5.2, 6.1_
  - _Requirements: 1.1, 1.4, 3.1, 3.2, 4.1, 6.1, 6.4, 7.2_

- [ ] 6.3 既存の 1 プロバイダの操作と経路の排他を整える
  - 経路の接続・切断と、プロバイダの切替が同時に実行されないようにする。段数 2 以上の経路の間は、切替を拒否する
  - 完了条件: 経路の実行中に切替を要求すると拒否され、段数 1 の接続と切替は今の挙動のまま動く
  - _Depends: 6.1_
  - _Requirements: 1.3, 5.3_

- [ ] 7. 経路の API
- [ ] 7.1 経路の要求・状態・変更の拒否を HTTP で提供する
  - 経路の要求（接続・切断）と状態の取得を提供し、読み取り専用の段の変更は拒否して理由を返す。スキーマは TypeBox で定義する
  - 完了条件: 経路の要求で状態が返り、読み取り専用の段の変更が拒否され、生成された API クライアントに新しい操作が含まれる
  - _Depends: 6.2_
  - _Requirements: 1.4, 2.5, 5.1_

- [ ] 8. 検証（検証サーバ）
- [ ] 8.1 段数 1・2・3・5 の経路を、出口コンテナ方式で確かめる
  - 異なる提供元の組み合わせを含む経路を、この実装で接続し、LAN（検証用のクライアント）からの通信が出口の外部 IP で出ること、各段のトンネルに受信があったことを記録する
  - 完了条件: 4 つの経路すべてで出口の IP が想定どおりになり、結果を記録する
  - _Depends: 7.1_
  - _Requirements: 1.1, 1.2, 1.3, 3.1, 6.1_

- [ ] 8.2 段の再作成の前後でログインが残ることを確かめる
  - 段のコンテナを作り直し、同じデバイスのログインが残ることと、未ログインの段で接続が止まることを確かめる
  - 完了条件: 作り直し後にログイン確認が成功し、ログインを外した段では `relogin-required` が返る
  - _Depends: 5.4, 8.1_
  - _Requirements: 7.1, 7.2_

- [ ] 8.3 トンネルを切ったときの遮断と、長い転送の結果を確かめる
  - 出口のトンネルを切ったとき、LAN の通信が遮断されることを確かめる。段数ごとに 10 MB 以上の取得を行い、全量の取得と途中終了を記録する（長い転送は注意事項であり、要件の制約ではない）
  - 完了条件: 遮断の結果と、長い転送の結果を discovery の section 17 に追記する
  - _Depends: 8.1_
  - _Requirements: 4.1, 4.4, 6.3_
