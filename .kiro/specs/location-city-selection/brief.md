# Brief: location-city-selection

## Problem
都市を指定して接続できる VPN プロバイダ（ProtonVPN・AdGuard VPN）で、接続先を国単位か都市の平らな一覧でしか選べない。
利用者は、プロバイダの機能を最大限生かし、国を選んだ後に都市を選んで接続したい。どのプロバイダでも同じ操作で選べることを重視する（UI の一貫性）。

## Current State
- **ProtonVPN**:
  - 接続先の一覧は `countries list`（国の名前とコード）だけで作る。接続は `connect --country <コード>` のみ。
  - 公式 CLI には、都市の一覧 `cities list <国コード>`（City・Features の表）がある。ログインが必要で、無料プランでは使えない（国指定と同じ）。
  - 運用中のランナーの CLI は proton-vpn-cli 1.0.5（`protonvpn` の実行時の表示で確認）。検証サーバの 1.0.3 は古いため、基準にしない。
  - サーバは 18,671 台（ランナーのサーバ一覧の読み取りで確認）。全サーバに識別名（`JP#151`、`CH-US#13`、`US-FREE#48` など）があり、重複はない。
  - 197 都市のうち 196 都市が複数サーバを持つ（例: Chicago は 897 台。うち直接接続 877、Secure Core 20）。
  - 都市の行は、都市内の最速サーバを 1 台選んで接続する形にする。アプリの表示台数と、この数の差は未確認（表示を絞っている可能性がある）。
- **同名の都市（ProtonVPN）**:
  - 国をまたぐ同名の都市は、現在のサーバ一覧に 0 件。
  - ただし CLI は `--city` を指定すると `--country` を無視し、都市名だけで全国から最速のサーバを選ぶ（1.0.3 のソースで確認）。
  - `cities list` は都市名だけを返し、サーバ名は返さない。サーバ名は、サーバ一覧（キャッシュ）からしか得られない。
- **AdGuard VPN**:
  - 一覧は都市の平らな行（ping 付き）。国だけを選ぶ手段は画面に無い。
  - CLI のヘルプは、`connect -l` が都市名・国名・ISO コードを受け付けると書いている（ヘルプで確認。実際の接続は未確認）。
  - 運用中のランナーの一覧は 81 都市、62 か国。都市名の重複は 0 件。`(Virtual)` の付いた都市が 3 つある。
  - 接続は未ログインでは試せないため、国の指定と「都市, 国」の形式の挙動は、実装時に確認する。
- 本体のパーサは、都市列付きの表を既に扱える。
- 無料プランの参考一覧（plan-locations）は、サーバ一覧のキャッシュから都市を読んでいる。

## Desired Outcome
- 両プロバイダで、同じ UI の一覧になる。国の行を開くと、その国の都市が一覧の下に並ぶ。
- 国の行からは国を指定して接続する（ProtonVPN は `--country X`、AdGuard VPN は国コードの指定）。
- 都市の行からは都市を指定して接続する。ProtonVPN は、都市内の最速サーバの識別名（例: `CH-US#13`）で指定する。AdGuard VPN は都市と国を添えた指定を想定する。
- ProtonVPN の都市の一覧は、その国を開いたときに初めて取得し、保存する。国ごとに一度だけ取得する。
- ping を取得できるプロバイダは ping の順、取得できないプロバイダは国名の順に並べる。
- 都市の一覧のタブは「最速サーバ」「サーバを選択」。最後に選んだタブは、プロバイダごとに保存する（次の国の選択で、そのタブから始める）。件数の指定と、表示方法の切り替えは撤回した。
- 一覧の UI の細部（戻る操作・タブの位置・お気に入りの粒度・表示する内容）は、`.kiro/steering/ui-conventions.md` の規約に従う。

## Approach
- **採用**: 一覧の UI は、プロバイダによらず「国の行の下に都市」の 1 種類にする。プロバイダごとの差（都市の取得の仕方・接続の引数）は `vendors/<ID>/profile.json` の宣言に書く。本体は宣言を読んで動く（ベンダー固有の分岐を増やさない）。
  - ProtonVPN: 都市の一覧は国ごとに遅延して取得し、保存する。サーバ名（識別名）は、サーバ一覧（キャッシュ）から取る。
  - AdGuard VPN: 国の一覧と都市の一覧は、既存の一覧（都市の行）から作る。
- **不採用**: 全国の都市を一度に取得する（ProtonVPN）。国の数だけ CLI を呼ぶことになり、初回が遅く、更新の手間も増える。
- **改訂（以前の不採用の取り消し）**: サーバ一覧のキャッシュ（`VPN/serverlist.json`）を読む方針を採用する。サーバ名（識別名）を得るために必要で、ユーザーが承認した。CLI の内部の形式に依存するため、読み取りの処理は宣言と検査で守る。
- **不採用**: AdGuard VPN の平らな一覧をそのまま残す。プロバイダ間で UI が揃わないため。

## Scope
- **In**:
  - profile の宣言: 都市の一覧の取得と、国・都市・サーバ名を指定した接続の引数
  - ProtonVPN: 国ごとの都市の一覧の取得と保存、サーバ一覧からの識別名の取得
  - AdGuard VPN: 一覧を国の下に都市を並べる形にし、国を指定した接続を加える
  - 両プロバイダで共通の一覧の表示（国の行の下に都市）と、国・都市への接続
  - 都市の一覧のタブ（「最速サーバ」は都市の選択で終わる。「サーバを選択」は都市の全サーバの一覧へ進む）と、その設定の保存
  - 無効のサーバは一覧に出さない（選べないものは表示しない。フィルタにはしない）
  - 無料と有料は、フィルタにせず同じ一覧に並べ、行ごとに階層（無料・有料）を表示する
  - ping の順と国名の順の並べ替え（ping を取得できるかどうかで分ける）
  - お気に入り・前回接続への対応（都市の ID は既存の形式 `jp-tokyo` を使う）。お気に入りの粒度は、都市（「最速サーバ」）とサーバ（「サーバを選択」）の 2 種類。プロバイダごとに保存する
  - 上記の一覧の表示（情報行・説明・ヒントは出さない。規約に従う）
  - E2E のモック（mockproton）の `cities list` と、都市指定の接続への対応
  - `vendors/protonvpn/` の更新（ユーザーが許可。宣言・Dockerfile・モックを含む）
- **Out**:
  - 無料プランの都市指定（国指定と同じく使えない）
  - 都市の座標と距離（`location-distance-sort` で扱う。別の仕様として並行させる。下記）

## Boundary Candidates
- 宣言（profile）の拡張と、都市の一覧・サーバ一覧の解析（国・都市・サーバ名の指定を含む）
- ProtonVPN の国ごとの都市の一覧の取得と保存、サーバ一覧からの識別名の取得
- 共通の一覧の表示（国の行の下に都市）と、国・都市への接続
- 並べ替え（ping の順・国名の順）

## Out of Boundary
- 距離と座標（`location-distance-sort`）
- 接続・切断の処理の変更（国・都市・サーバ名の引数を渡すことを除く）
- プラン制限の判定（既存の capability の仕組みをそのまま使う）

## Upstream / Downstream
- **Upstream**: 接続先の一覧（`api/src/locations/`）、profile の宣言（`api/src/profile/`）、接続（既存の connect）、お気に入り・前回接続の保存、E2E のモック（`e2e/vendors/mockproton`）、一覧の画面（`web/src/components/dashboard/`）
- **Downstream**: `location-distance-sort`（都市の座標と、都市単位の距離順）

## Existing Spec Touchpoints
- **Extends**: なし（接続先の一覧の拡張）
- **Adjacent**:
  - `location-distance-sort`: ping を取得できないプロバイダの距離順。ユーザーの指示で、別の仕様として並行させる。本 spec の「国名の順」と、距離順のどちらを既定にするか（または切り替えるか）は、要件で決める。都市の距離は、要件 3（座標の取得）と要件 4.5（国単位）の変更が必要。
  - `e2e-tests`: E2E のモックと、E2E の範囲。
  - `vendor-live-e2e`: 実 VPN での国・都市・サーバ名への接続を確かめる対象になりうる。

## Constraints
- 本体のコード（コメントを含む）に、ProtonVPN・AdGuard VPN の名前と CLI のバイナリ名を書かない（中立性の検査の対象）。
- `cities list` の出力は、1.0.3 のソースでは「Cities in <国名>:」の見出しに続く表（City・Features 列）。1.0.5 でも同じ形式であることを、ランナーのソースで確認した。
- サーバ一覧（キャッシュ）の実データは、運用中のランナーで読み取り専用で確認した（18,671 台）。実装時は、ログイン後の取得の仕組みで同じ形式かを再確認する。
- 確認事項（要件で決める）:
  - 「サーバを選択」の一覧で、AdGuard VPN（サーバの段がない）の扱い。都市の ☆ を残すか。
  - サーバの一覧に Score を値として残すかどうか（説明は出さない）。
  - 国の行の並べ替え（ping の順と国名の順）と、`location-distance-sort` との関係。
  - 国の行に出す ping の扱い（AdGuard VPN は都市ごとの ping。国の行は最小値などを想定）。
  - 都市の一覧のキャッシュの更新の方針
  - 取得に失敗したときの表示
