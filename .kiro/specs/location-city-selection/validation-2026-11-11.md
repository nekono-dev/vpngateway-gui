# 2026-11-11 E2E 失敗の修正と再検証

## 修正

- 接続時のカタログ読み込みが Secure Core・停止中のサーバを除外せず、一覧からは除外されたサーバを都市の最速接続で選択していた。`availableServers` を共有し、一覧・接続で同じ型検査と選別を使う。Score が小さい除外対象を含む回帰テストで確認。
- 都市一覧専用コマンドのないプロファイルで都市 API が 501 になっていた。`listCities` 宣言がなければ既存の接続先一覧から都市を返す。ping を保持し、再取得も同じ取得経路を使う。GET/refresh の回帰テストを追加。
- hosted E2E の Proton モックの status が固定の接続先を返していた。保存した接続先を返すよう修正し、サーバ指定接続後の status を検査。

## 検証環境

検証サーバ 192.168.3.240 の専用 LXD コンテナ `e2e-city-selection-20261110`（Ubuntu 24.04、4 CPU、8 GiB）を利用。既存のホスト上のアプリとは別環境。

- root でなく ubuntu で `npm run test:e2e` を実行。UID による経路分離の前提を守る。
- LXD 内の名前空間作成に必要な proc/sys マウントの syscall interception を有効化。
- sudo 経由の模擬 ISP 起動で node が見つかるよう `/usr/local/bin/node` を用意。
- DHCP が作成した 1.1.1.1/8.8.8.8 宛の物理回線固定経路を除去。1.1.1.1 は VPN 検出の経路問い合わせ先なので、固定経路があると模擬 VPN のデフォルト経路を検出できない。
- 転送した作業ツリーを一時 Git リポジトリにコミット。lifecycle が `HEAD~1` へ更新するため、空ツリーを直前コミットにしない。

- 最終の全群 JSON 集計: 合格 73 件 / 不合格 0 件。
- gateway の再実行は既存 run.sh の lifecycle 呼び出しを除き、対象ループを gateway だけにした一時スクリプトを使用。準備・実行・後始末・集計は既存処理。一式実行が単独で終了コード 0 になったという主張ではない。gateway 再実行の終了コードは 0。
