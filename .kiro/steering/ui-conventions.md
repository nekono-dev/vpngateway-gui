# UI 規約

利用者向けの画面（主に接続先の一覧）で、操作と見た目を一貫させるための規約。仕様（requirements・design・tasks）と実装は、この規約に従う。規約と仕様が食い違うときは、仕様の側を直す。

## 一覧の階層と戻る操作

- 接続先の一覧は、国 → 都市 → サーバの順に詳細になる。段数はプロバイダによって違ってよいが、操作の仕方は同じにする。
- 一つ下の段に進んだら、一覧の上部の左に「‹ 上の段の名前」の戻るボタンを置く（国の一覧に戻るときは「‹ 国一覧」）。
- 戻る操作は、戻るボタンと、一覧の上で右方向へのスワイプ（左から右）の 2 つ。左方向のスワイプでは戻らない。
- 最上段（国の一覧）では、スワイプで戻らない。
- 戻るボタンとタブは、上部の同じ行に左詰めで並べ、間に空白を作らない。タブは戻るボタンの右に続ける。
- 段を戻っても、前の段の選択状態とタブの状態は保つ。

## タブ

- 国の一覧のタブは「すべて」「お気に入り」。
- 都市の一覧のタブは「最速サーバ」「サーバを選択」。
  - 「最速サーバ」: 都市を選ぶと、その都市の最速のサーバへの接続で終わる（次の段へは進まない）。
  - 「サーバを選択」: 都市を選ぶと、その都市のサーバの一覧へ進む。
- 都市の一覧で最後に選んだタブは、プロバイダごとに設定として保存する。次に国を選んだときは、保存された方のタブで始める。

## お気に入り

- 登録する粒度は、利用者が見ている段による。
  - 都市の一覧（「最速サーバ」）では、都市を登録する。
  - サーバの一覧では、サーバを登録する。
- 「サーバを選択」の都市の一覧では、都市の ☆ を出さない（サーバの ☆ で登録する）。
- お気に入りのタブには、都市とサーバの両方を表示する。
- ☆ を押しても、その行は選ばれない（☆ と行の選択は、別の操作にする）。
- お気に入りは、プロバイダごとに保存する。

## 表示する内容

- 操作に必要な情報だけを表示する。
- 件数や条件の要約の行（例: 「全サーバ N 台（有効・直接接続）」）は出さない。一覧の上部に固定する情報も置かない。
- 説明文・ヒント・案内は、利用者が操作の前に必要とするものだけを出す。次は出さない。
  - 操作の方法（例: 「右にスワイプで戻れます」）
  - 用語の説明（例: Score の意味）。説明のための折りたたみや吹き出しも置かない。
  - 利用者が常に必要としない案内（例: 「このプロバイダでは ping 計測を利用できません」）
- 検索窓は、国の一覧と都市の一覧にだけ出す。サーバの一覧には出さない。
- 接続中・前回のバッジは、既存の表示に従う。

## 寸法と見切れ

- 高さに 100vh を使わない。一覧は内容の高さに合わせ、上限を超えたときだけ一覧の中でスクロールする。
- 横幅は、携帯幅（約 390px）でも横スクロールを出さない。

## 適用範囲

- この規約は、接続先の一覧（国・都市・サーバの一覧と、その上部の操作）に適用する。
- 他の画面は、既存の画面の作り方に従う。

## 未決定

- AdGuard VPN には、サーバの段がない。「サーバを選択」の扱い（都市の ☆ を残すか）は、仕様で決める。
- サーバの一覧に、Score を値として残すかは、仕様で決める（説明は出さない）。
