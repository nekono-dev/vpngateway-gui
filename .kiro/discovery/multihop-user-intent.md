# 二段接続: 利用者の意思（画面の検討は保留）

このファイルは、利用者が決めたことだけを残す。画面の具体的な構成と共通 UI の変更は、既存の別 spec（`location-city-selection`・`location-distance-sort`）の対応後に統合して検討する。

## 進め方
- 画面の作成とバックエンドの実装は別で扱う。最初の spec はバックエンド（`multihop-backend`）。
- 画面（`multihop-ui`）は、既存の spec が変わった後に、改めて discovery から始める。

## 入口（1 段目）の選び方
- 方式は、ランダム・プロバイダ選択・手動選択の 3 つ。既定値はランダム。
- プロバイダ選択の既定の提供元は、出口と同じプロバイダ。
- プロバイダ選択の中身は、プロバイダごとの方式に従う（AdGuard VPN は ping の最小、ProtonVPN は Score の最小）。
- 手動選択では、利用者が一覧から 1 つ選ぶ。それ以外の方式では、選ばれたサーバを表示するだけで、利用者は変えられない。

## 段の構成
- 段数は 2 段に限らず、n 段に対応する（2026-11-08 の決定。段数は出口の 1 つ前から順に増やせる作り）。
- 段数の上限の値は、設計で決める。
- 出口の段で二段接続を使うかどうかを選べる。

## 切断時の動作（kill switch）
- どちらの段の切断でも通信を遮断する（既定）。
- 2 段目（出口側）が切れたときは 1 段で継続する、という選択も設けられるようにする。

## 検証と上限（2026-11-08 の決定）
- 最初の検証は検証サーバ（192.168.3.240）で行う。実ベンダへのログインは可能。
- この spec では同時接続の上限を設けない（注意表示のみ）。検証は 5 段まで行う（上限 5 本は検証の到達点で、要件ではない）。
- 別経路（複数の経路を同時に張ること）は、この spec の要件に含めない。
- MTU を増やす方向の調整も対象にする。ルータへの設定が必要な場合も対応できる。

## 規約（同時接続の上限）
- 注意の表示だけを行う。上限の検出や拒否は行わない。

## Secure Core
- 既存の Secure Core 機能は、二段接続に置き換える。

## 未決（利用者の判断待ち）
- 異なるプロバイダを組み合わせるかどうか（今の API は 1 プロバイダ前提のため、影響が大きい）。
